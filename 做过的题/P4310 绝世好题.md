# 优化

涉及到位运算，总会有一些奇妙的性质
优化方向无非就两个
1. 优化状态，把状态维度缩小
2. 优化转移，加快转移速度
显然状态不能再优，便考虑在转移上下功夫
因为是&运算，所以参与运算的几个数中，必须 **存在一位，使每一个数的二进制上的这一位都为1**
那从这里能推出什么呢
**一个数列能否成为合法的序列，取决于是否存在一位，使得数列中的每一个数的这一位都为1**(疑似废话)
**而所有某一位上为一的数构成了数列中最大数的二进制位数个集合**
***
现在问题转化为了
在一个n\*m的平面上，有些点为1，另一些为0
	你只能在为1的格子上驻足
	你横着可以一次跨过任意多个为0的格子、
	你竖着不能跨过为0的格子
	你最多能走过多少个横坐标，换句话说，你的足迹的横坐标的集合的大小
```cpp
0101011110001000000
0001000100010010001
1010001100001001001
1111000001111001000
//类似这样一个方阵
```
建图，拓扑排序，求最长路
```cpp
for(int i = 1; i <= n; i++) {
	int last = 0;
	for(int j = 1; j <= m; j++)
		if(a[i][j]) {
			in[j]++;
			g[last].push_back(j);
			last = j;

}
```

# 总结与感悟
其实一开始我想到暴力就已经江郎才尽了，没有思考的方向
不知道往位运算，二进制的深层性质中思考
其实应该有一个这样的逻辑链条：
	想到暴力dp --> 意识到要优化的地方为状态的转移 --> 发现转移时每一次都要从头扫到当前位置，怀疑这中间是不是有重叠子问题 --> 发现与运算的性质，将问题进一步抽象 --> 思考，解决新问题
有时候把一个抽象的问题转化为一个平面上的点线面问题会更直观一些，但是否真的有利于思考还有待商榷
