结合你前面问的“OI中能否使用并行优化”，这张图给出了 OI 中真正的“并行”答案：**既然无法用多线程，那就把一个 64 位整数当成 64 个独立的布尔变量（0/1）来同时计算，从而实现常数级的 64 倍加速。**

### 前言：基本思想
> *“在 OI 这样的单线程程序中……用单条指令处理多组数据。把数据中的一个字(word)看成同时存储和处理多个位的方式。”*

这里指的是 **SWAR (SIMD Within A Register)** 技术。例如，C++ 中的 `unsigned long long` 有 64 位，你可以把 64 个互相独立的 0/1 状态压进这一个变量里。一次 `&`、`|`、`^` 位运算，就相当于对这 64 个状态**同时**进行了计算。

### 问题 0：位运算基础
让你去学 `__builtin` 系列函数，比如：
*   `__builtin_popcount(x)`：求 x 二进制中 1 的个数。
*   `__builtin_ctz(x)`：求 x 二进制末尾 0 的个数。
*   `__builtin_parity(x)`：求 x 二进制中 1 的个数的奇偶性。
这些是硬件指令级别的加速，通常只需要 1 个 CPU 周期。

### 第一部分：并行处理多个位（模拟算术逻辑）
*   **问题 1.1**：输入 `a[32]` 和 `b[32]`，它们每个元素是 0 或 1，代表一个 32 位的二进制数。要求写程序算 `a+b` 和 `a*b`，且**中间过程的所有变量只能是 0/1，不能出现整数加法**。
    *   **解释**：这是在让你用“逻辑门”（与、或、非、异或）来手搓一个加法器（全加器）和乘法器。
*   **问题 1.2**：改为输入 64 个数的数组，但每个变量变成一个 64 位整数，问能否同时算 64 组？
    *   **解释**：这就是并行。因为第 1 组的数据在 bit 0，第 2 组在 bit 1……当你对这 64 位整数做按位与、按位异或时，这 64 组加法/乘法就**同时算完了**。

---

### 第二部分：状态压缩与计数（非常经典的位运算题）
*   **问题 2.1**：给定 \(n\) 个 64 位以内的非负整数，求二进制每一位上 1 的总个数。常规做法是两层循环 \(O(nw)\)。
*   **问题 2.2**：能否时间复杂度低于 \(O(nw)\)？
    *   **解释**：这是著名的“如何用位运算快速统计多位信息”。既然我们要统计 64 个位置上的 1 的个数，计数值最大是 \(n\)。如果 \(n<16\)，我们可以用 4 个 bit 来存一个计数。一个 64 位整数刚好可以存 16 个计数器。于是我们把原本要算 64 次的循环，压缩成了只有 4 次左右的操作。这需要用到分治的加法（SWAR 加法），非常巧妙。

---

### 第三部分：模拟 DFA（自动机与无分支编程）
*   **背景**：如果一个程序全是 `if/else` 这种条件分支，CPU 会因“分支预测失败”而变慢。如果能把逻辑写成纯 0/1 运算（无分支），就能并行。
*   **问题 3.1**：如何把 DFA（确定性有限自动机）的转移过程写成只有 0/1 变量的代码？
    *   **解释**：对于 DFA 的输入 \(x \in \{0,1\}\) 和当前状态 \(S\)，转移函数 \(f(S, x)\) 可以写成一个真值表。用位运算的与、或、异或来实现状态转移。
*   **问题 3.2（BZOJ 2908 部分）**：树上路径，每个点有权值。从 \(a\) 走到 \(b\)，把路径上的权值依次做 **NAND（与非）** 运算。
    *   **解释**：NAND 运算**不满足结合律**（即 `a NAND (b NAND c)` 不等于 `(a NAND b) NAND c`）。因此，线段树/树剖合并信息时，不能简单地把两个区间的答案 NAND 起来，必须维护“输入 0 进去得到什么，输入 1 进去得到什么”这种函数信息。
    *   **如何位运算并行？**：因为输入只有 0 和 1，NAND 函数总共就 4 种（例如：永远输出 0，永远输出 1，输出原值，输出取反）。我们可以用一个整数来表示这种函数映射，这样不仅避免了分支判断，还能直接合并。

---

### 总结：这张图想教给你什么？
1.  **改变思维**：不要把 `int` 或 `long long` 仅仅当成一个数字，把它当成一个**长度为 64 的布尔数组**。
2.  **消除分支**：能用 `&`、`|`、`^` 解决的地方，不要用 `if`。
3.  **降维打击**：通过这种 64 位压位操作，原本 \(O(n)\) 的复杂度变成了 \(O(n/64)\)，原本 \(O(nw)\) 的问题可以优化到 \(O(n)\) 或更优。在 OI 的极限卡常（比如 \(n=10^5\)，时限 1 秒）中，这能救命。
